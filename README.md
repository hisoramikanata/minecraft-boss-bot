# minecraft-boss-bot

[Mineflayer](https://github.com/PrismarineJS/mineflayer) を使った Minecraft 自動プレイBotです。
自分が所有/参加許可のあるサバイバルサーバーに接続し、チャットコマンドで **エンダードラゴン・ウィザー・ウォーデン** の討伐を自動化します。
`!progress start` を使うと、装備なしのサバイバル開始状態から資材収集・ネザー/エンド探索・ボス討伐までを一気通貫で自動進行させることもできます(実験的機能、詳細は下記)。

## 重要な注意事項

- **必ず自分が所有するサーバー、または管理者から自動操作(Bot)の使用許可を得たサーバーでのみ使用してください。** 許可のないマルチプレイサーバーでBotを使うと規約違反・BANの対象になります。シングルプレイの「LANに公開」機能や自前の統合版/Java版サーバーでの利用を推奨します。
- **このセッションには実際のMinecraftクライアントは含まれていません。** このリポジトリはBotのソースコードのみを提供します。実行するにはご自身のPC/サーバー環境でNode.jsを使って起動してください。
- ウォーデンは近接攻撃で即死級のダメージを与えてくるため、デフォルトでは **回避のみ** を行います(`WARDEN_AVOID_ONLY=true`)。応戦させる場合は自己責任で設定を変更してください。
- Botの行動(既存構造物の破壊・設置、PvPなど)によって意図しない被害が出る可能性があります。特にウィザー召喚時はブロック設置・爆発を伴います。

## 必要環境

- Node.js 18以上
- 自分が管理するMinecraft Java Edition サーバー(推奨バージョン: 1.20.x)
- Bot用のアカウント(オフラインモードのユーザー名、または正規Microsoftアカウント)

## セットアップ

```bash
npm install
cp .env.example .env
# .env を編集してサーバー情報を設定
npm start
```

### .env の主な設定項目

| 変数 | 説明 |
|---|---|
| `MC_HOST` / `MC_PORT` | 接続先サーバー |
| `MC_USERNAME` | Botのユーザー名 |
| `MC_AUTH` | `offline` または `microsoft` |
| `MC_VERSION` | サーバーのバージョン(空で自動検出) |
| `MC_ADMIN` | コマンドを許可するプレイヤー名(空で全員許可) |
| `WARDEN_AVOID_ONLY` | `true` ならウォーデンとは戦わず回避のみ行う(推奨) |

## チャットコマンド

Minecraft内のチャットからBotに指示します。

| コマンド | 内容 |
|---|---|
| `!help` | コマンド一覧を表示 |
| `!gear` | 所持品から最良の武器・防具を自動装備 |
| `!fight wither` | ウィザーを討伐(必要素材が揃っていれば自動召喚も行う) |
| `!fight dragon` | エンダードラゴンを討伐(**事前にジ・エンドへ移動しておく必要があります**) |
| `!fight warden` | ウォーデンに遠距離で応戦(`WARDEN_AVOID_ONLY=false`の場合のみ) |
| `!avoid warden` | ウォーデンから距離を取って回避する |
| `!progress start [フェーズ名]` | **サバイバルを装備なしの状態から自動で進行し、エンダードラゴン討伐までを一気通貫で行う**(下記参照)。フェーズ名を指定すると途中から再開できる(例: `!progress start diamond`) |
| `!progress phases` | 指定可能なフェーズ名の一覧を表示 |
| `!status` | 現在のHP・満腹度・実行中タスクを表示 |
| `!stop` | 実行中のタスクを中断(区切りの良いところで停止。即時中断ではありません) |

## 各ボスの自動化ロジックと制約

### ウィザー
- ソウルサンド/ソウルソイル4個 + ウィザースケルトンの頭3個を所持していれば、T字型に設置して自動召喚します。
- 召喚直後の無敵時間中は距離を取り、無敵解除後は弓と近接攻撃を距離に応じて使い分けます。
- HPが下がると自動で後退し、`auto-eat`プラグインにより食料があれば自動で回復します。

### エンダードラゴン
- **ジ・エンドに入っている状態からの利用を想定しています**(ストロングホールドの探索・エンドポータルの起動は自動化していません)。
- まずエンドクリスタルを弓で遠距離から破壊し、その後ドラゴンに接近して攻撃します。
- ドラゴンがポータル上に着地して静止しているタイミングを狙って近接攻撃し、飛行中は弓で牽制します。

### ウォーデン
- デフォルトでは検知されると即座にしゃがみ移動で安全距離(20ブロック以上)まで離脱します。採掘・設置・走行など振動を出す行動は行いません。
- `WARDEN_AVOID_ONLY=false` の場合のみ応戦モードが有効になりますが、**近接は一切行わず**、安全距離を保ちながら弓で攻撃する遠距離キルサイクルのみを実行します。それでも非常に危険なため、装備を万全に整えたうえで自己責任で使用してください。

## `!progress start`: サバイバル1からの完全自動進行

装備・資材を一切持たない状態から、以下のフェーズを順番に自動実行します。

1. 木材確保・木のツール作成
2. 石材採掘・石のツール作成
3. 食料確保(狩猟・調理)
4. 石炭/鉄鉱石採掘 → 精錬 → 鉄ツール・防具作成
5. ダイヤモンド採掘 → ダイヤツール・防具作成
6. 村を訪問(任意、`/locate`コマンドで検索)
7. 荒廃したポータルを探して修復・着火(見つからない/使えない場合は黒曜石を集めて0から建築)、ネザーへ突入
8. ネザー要塞探索、ソウルサンド/ブレイズロッド/ウィザースケルトンの頭骨collect
9. ウィザー討伐
10. オーバーワールドへ帰還
11. エンダーマン討伐によるエンダーパール収集、エンダーの目の作成
12. エンダーの目を投げて方向を推定しながらストロングホールドへ接近・掘削・ポータル起動
13. ジ・エンドへ突入し、エンダードラゴンを討伐

村・荒廃したポータルの検索は`/locate`コマンドを使うため、ワールドでチート(コマンド)が有効になっている必要があります(「LANに公開」でチートONにした場合など)。

各フェーズは失敗すると内容に応じて「致命的(進行停止)」または「任意(スキップして続行)」として扱われます。食料確保などは任意、採掘や次元移動などコアパスは致命的フェーズです。

### 自動インベントリ管理・道具の自動再クラフト

- 採掘・収集ループ中、荷物の空きが少なくなると自動で空きを作ります。手順は「①近くの拠点チェストに丸石・土・砂利などの不要品を預ける → ②チェストがまだ無ければその場で新しく作って預ける → ③それでも空きが足りなければ不要品をその場に捨てる」の順(道具・武器・防具・食料などの重要アイテムは対象外)。採掘トンネルの中など周囲が岩壁で設置場所が無い場合は、横を1つ掘ってから設置します。
- 採掘中に持っているべきツルハシが壊れて無くなっていた場合、材料があれば自動で作り直してから採掘を続けます(数回の採掘試行ごとに確認)。作り直す際は、そのフェーズで必要な最低tierではなく、**今の所持品で作れる最も上位のtier**(ダイヤ>鉄>石>木の優先順)のツルハシを作ります。

### 特に実験的・高リスクなフェーズ

このリポジトリの他の機能(ボス戦単体など)と比べ、以下は本物のMinecraftサーバーでの検証を行えていないため、動作しない・地形によって失敗する可能性が高いことを理解した上で使用してください。

- **黒曜石の溶岩+水変換**: バケツ操作の正確な挙動はサーバー/バージョンで差異が出やすく、最も不安定な処理です。天然の黒曜石が見つからない場合のみ使用されます。
- **ネザー要塞探索**: マップ情報なしのランダム探索のため、溶岩地帯で行き詰まる・要塞が遠すぎて発見できない可能性があります。
- **ストロングホールド接近(エンダーアイ追跡)**: 投げたエンダーの目のエンティティ検出・方向推定はヒューリスティックです。座標を厳密に三角測量しているわけではなく、「進んでは投げる」を繰り返す簡易手法のため、時間がかかる・辿り着けないことがあります。
- **ポータル部屋探索**: マップ構造を持たないため、石レンガの通路をランダムに掘り進めて探します。効率が悪く、行き止まりで停止することがあります。

これらのフェーズで詰まった場合は、`!stop` で中断し、該当地点まで手動でプレイヤーが誘導する、または必要アイテムを手渡す(`/give` など、自分のサーバーの権限がある場合)といった人力サポートを想定しています。

## 既知の制約

- ネザライト装備への強化(ネザライト鉱石採掘・鍛冶台での合成)は自動化していません。ダイヤモンド装備までです。
- ウォーデンの自動討伐・探索は行いません(仕様上、回避を最優先する設計です)。
- サーバー側の建築物・地形によっては、ブロック設置や移動経路の探索が失敗することがあります。
- 長時間(数時間規模)の自動実行を想定していますが、途中で死亡した場合は自動リスポーン後もそのフェーズから再試行を続けます(進行中のインベントリ内容によっては同じ場所からやり直しになる場合があります)。
